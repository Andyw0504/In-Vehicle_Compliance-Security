# 01 · 汽车电子与总线架构基础

> 先懂车，再攻车。E/E 架构、总线类型、网络拓扑是一切车辆安全工作的底图。

## 汽车电子系统分层

```
┌────────────────────────────────────────┐
│  车云通信层:  TBOX(4G/5G) / V2X / GNSS   │ ←远程攻击面
├────────────────────────────────────────┤
│  信息娱乐层:  IVI车机(Android/Linux) / 仪表 │ ←互联攻击面
├────────────────────────────────────────┤
│  车身控制层:  BCM / 车门车窗 / 空调 / PEPS │
├────────────────────────────────────────┤
│  动力底盘层:  发动机ECU / 变速箱 / ESP / EPS│ ←安全相关(Safety)
├────────────────────────────────────────┤
│  网关(Gateway): 域间隔离与路由            │ ←防御关键点
└────────────────────────────────────────┘
```

域域互联：传统分布式 ECUs（单车 70~150 个）→ **域集中式**（动力/底盘/车身/座舱/智驾五域）→ **中央计算+区域控制器（Zonal）**。

## 总线协议速查

| 总线 | 速率 | 典型用途 | 安全要点 |
|---|---|---|---|
| **CAN** | 500kbps(动力) 125kbps(舒适) | 主力控制总线 | 广播无认证、ID 竞争仲裁 |
| **CAN-FD** | 最高 5Mbps | 新平台控制总线 | 数据段扩到 64B，仍无原生认证 |
| **LIN** | 20kbps | 车窗/雨刮/座椅等低成本节点 | 主从结构，更弱防护 |
| **FlexRay** | 10Mbps | 线控底盘/冗余系统 | 时间触发，用得少 |
| **车载以太网** | 100/1000BASE-T1 | 智驾域/座舱域/OTA/诊断 | 继承 IT 网络安全问题+车载特化 |
| **MOST** | — | 旧款音响多媒体 | 已淘汰，了解即可 |

## CAN 核心机制（必背）

- **广播总线**：所有节点都"听见"所有报文，**没有源地址认证**——任何人都能伪造
- **仲裁**：ID 数值越小优先级越高（显性 0 赢）
- **帧结构**（标准帧 11 位 ID）：
  `SOF | ID + RTR | 控制(DLC) | 数据(0~8B) | CRC | ACK | EOF`
- **错误处理**：错误帧 + 错误计数器（TEC/REC≥256 → BUS OFF）
- 报文无时间戳无发送者身份 → 接收方默认"总线上的都是真的"

## 网关（Gateway）的角色

- 路由：动力网 ↔ 车身网 ↔ 信息网的报文转发与过滤
- 防御关键：**报文过滤白名单、域间隔离、诊断报文管控**
- 被攻破 = 攻击跨域（Jeep 案例：IVI 网 → 网关 → 动力/底盘网）

## 攻击面地图（后面章节展开）

| 攻击面 | 接口 | 攻击距离 |
|---|---|---|
| TBOX 蜂窝 | 4G/5G 数据+短信 | **无接触远程** |
| IVI | WiFi/蓝牙/USB/APP | 近场~远程 |
| RKE/PEPS | 315/433MHz RF、BLE | 中继攻击 |
| OBD-II | CAN 诊断口 | 物理接触 |
| OTA | 蜂窝/WiFi | 供应链/远程 |
| V2X | PC5/DSRC | 近场 |
| 充电桩/口 | PLC(CP) | 物理接触 |

## 动手环境预告（第 02 篇展开）

- Linux + **SocketCAN**（内核自带 CAN 协议栈）
- `vcan0` 虚拟总线：无硬件也能玩全套抓包/伪造/注入
- 硬件进阶：CANable / PCAN / Kvaser + 真车或台架
