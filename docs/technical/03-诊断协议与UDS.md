# 03 · 诊断协议与 UDS

> UDS（ISO 14229）是车企内部的"万能后门"，也是安全测试重点。诊断口既是维修入口，也是攻击入口。

## 诊断体系分层

```
ISO 14229 UDS        应用层(服务/SID)
ISO 15765-2 (DoCAN)  CAN 上的传输层(多帧拆包)
ISO 13400 DoIP       以太网上的诊断(新平台趋势)
ISO 15031 / SAE J1939  OBD 排放诊断(法规要求, 功能受限)
```

## UDS 常用 SID（服务标识）

| SID | 服务 | 用途/安全相关 |
|---|---|---|
| 0x10 | 诊断会话控制 | 01 默认 / 02 扩展会话 / 03 编程会话 |
| 0x11 | ECU 复位 | |
| 0x14 | 清除 DTC | 故障码 |
| 0x19 | 读取 DTC | |
| 0x22 | 读取 DID | 读版本号/序列号/标定 |
| 0x27 | **安全访问** | Seed-Key 解锁，进入受保护操作 |
| 0x29 | **认证**（2020 新增） | 基于证书的认证，逐步替代 0x27 |
| 0x2E | 写 DID | 写配置/标定（需先解锁） |
| 0x31 | 例程控制 | 自检/清学习值 |
| 0x34/0x36/0x37 | 请求下载/传输数据/传输退出 | **固件刷写三件套** |
| 0x85 | 控制 DTC 设置 | 刷写时关闭 DTC 记录 |

## 0x27 安全访问流程（必背）

```
诊断仪 → 27 01            (请求 seed, 级别1)
ECU   → 67 01 AA BB CC DD  (返回 4 字节 seed)
诊断仪本地计算 key = 算法(seed)     ←算法藏在固件里
诊断仪 → 27 02 KK LL MM NN (发送 key)
ECU   → 67 02              (解锁, 后续允许 2E/34 等服务)
```

**安全测试重点 = Seed-Key 算法逆向**：
- 从固件/APP 中定位算法（常见：CRC32、AES、简单异或、查表）
- 常见弱点：seed 与 key 线性相关、算法固定无秘钥、全系列车型共用同一算法

## 刷写流程（安全视角）

```
10 03(编程前提) → 27 xx(解锁) → 31 xx(擦除检查)
→ 34(请求下载, 指定地址长度) → 36(传输数据×N) → 37(退出)
→ 校验(签名/哈希) → 11 01(复位)
```

安全点：
- 固件包**签名验证**在哪一步？能否被绕过/降级？
- VBF/HEX/CONTAINER 格式的完整性保护
- 刷写过程中断（变砖/半砖状态）

## DoIP 要点（ISO 13400）

- 端口：**13400/tcp**（车辆发现 UDP 13400 组播）
- 车辆声明报文：VIN / ECU 逻辑地址
- 安全点：未认证的 DoIP 访问 = 拿到诊断通道；网关对路由激活(Routing Activation)的管控

## 诊断口攻击案例模式

1. **解锁后写入**：0x27 弱算法 → 解锁 → 0x2E 改配置/0x31 触发动作
2. **固件提取**：34/36 反向流程或调试口(JTAG/UART) → 拆算法/找密钥
3. **跨网关**：诊断报文路由到非预期网段（网关白名单缺陷）
4. **速度 spoof**：部分车型可通过诊断改车速信号影响 ABS/DTC

> ⚠️ 以上模式仅在**自有 ECU / 台架**上练习（可以买二手 ECU 或用开源模拟器）。
