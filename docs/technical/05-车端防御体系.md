# 05 · 车端防御体系

> 从"能攻"回到"能防"：车端纵深防御的技术栈，对应 21434 的缓解措施落地。

## 纵深防御总图

```
云/通信层:  TLS双向认证 · PKI证书体系 · V2X消息签名(IEEE1609.2)
接入层:    TBOX/IVI最小服务 · 防火墙策略 · APN专网隔离
车内网络:  网关过滤 · secOC报文认证 · ID/Frequency基线监控
节点内:    安全启动(Secure Boot) · HSM密钥保护 · 固件签名
运维层:    车队监控 · PSIRT · OTA修复 · IDS规则更新
```

## 1. 安全启动与固件保护

- **信任链**：ROM → Bootloader(验签) → 应用固件(验签)，逐级校验签名（RSA-2048/ECC）
- 固件包签名 + 防降级（版本号单调递增，对应 R156）
- 密钥/证书存储：**HSM**（EVITA Full/Medium/Light 分级）或 SHE
- 调试接口管理：JTAG/UART 量产锁定（熔丝/口令）

## 2. secOC（AUTOSAR Secure Onboard Communication）

解决 CAN"无认证无新鲜度"的结构性缺陷：

```
原报文: [ID][Data(0~8B)]
secOC:  [ID][Data压缩][FreshnessValue低位][MAC(64bit, CMAC-AES128)]
        MAC = MAC(MACKey, ID+Data+FreshnessValue)
```

- **MAC**：伪造报文无密钥算不出 → 解决"认证"
- **新鲜度计数器**：高位计数器(全局/节点同步) + 低位随报文传输 → 解决"重放"
- 代价：CAN-FD 才装得下（8B 数据不够塞），带宽与延迟开销，密钥分发体系（产线注入）

## 3. 网关过滤与域隔离

- 白名单路由：ID/方向/周期 合法才转发
- 诊断报文特殊管控（0x27 解锁后才放行敏感路由）
- 关键域（动力/底盘）与其他域**物理/逻辑强隔离**
- 参考开源：EGW（Ethernet Gateway）架构研究

## 4. 入侵检测 IDS（车端+车队）

| 层级 | 检测内容 | 技术手段 |
|---|---|---|
| 总线 IDS | 异常 ID、频率漂移、DLC 异常、周期抖动 | 规则/基线 + 机器学习 |
| 节点 IDS | ECU 内部系统调用、内存异常 | 轻量 agent（资源受限） |
| 车队 IDS | 整车行为异常上报、聚合分析 | 云端 SIEM/UEBA |

- 标准参考：AUTOSAR IDS 规范（Sensor/Report/Manager 分层）、ISO/SAE 21434 运维监控要求
- 评估指标：误报率（误报会毁掉 SOC）与漏报率的平衡

## 5. OTA 安全（R156 / ISO 24089 / Uptane）

- **Uptane** 框架核心：全量镜像仓库(映像目录签名) + 车端 Director(逐车定制签名) 双签名体系
- 防降级攻击：版本/时效元数据
- A/B 分区回滚机制
- 升级服务器安全（等保/入侵防护/供应链审计）

## 6. 密钥与 PKI 体系

- 车辆身份证书：产线注入，HSM 保护，支持吊销
- 后端互信：双向 TLS、证书轮换
- secOC 密钥分发：按平台/车型/ECU 分级管理
