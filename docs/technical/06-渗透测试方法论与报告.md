# 06 · 车辆渗透测试方法论与报告

> 把攻击面知识变成可交付的工作方法：范围界定 → 测试 → 报告，对应准入证据包要求。

## 测试类型矩阵

| 类型 | 对象 | 环境 | 深度 |
|---|---|---|---|
| 总线测试 | CAN/CAN-FD 网络 | 台架/试验场 | 报文伪造/注入/DoS/网关绕过 |
| 诊断测试 | UDS/DoIP 服务 | 台架 | 0x27 强度、未授权服务可达性 |
| 通信测试 | TBOX 蜂窝/V2X | 试验场+隔离网络 | 协议 fuzz、中间人 |
| 近场测试 | 蓝牙/WiFi/RKE | 屏蔽室/实验室 | 配对绕过、重放、中继 |
| 应用测试 | 车机 APP/OTA 服务器 | 普通安全实验室 | 常规 Web/移动测试方法 |
| 固件测试 | 各 ECU 固件 | 实验室 | 提取、逆向、密钥硬编码检查 |

## 标准流程

```
1. 范围与授权书      ← 车型/ECU清单/接口清单/测试边界/时间窗(书面!)
2. 信息收集          ← 架构图/网段划分/DBC/固件版本/文档
3. 威胁建模          ← 复用项目 TARA, 未覆盖面补充分析
4. 测试执行          ← 按 TARA 高风险路径优先, 每项留证据(抓包/日志/截图)
5. 漏洞确认与评级    ← 影响×可行性, 对齐 CVSS + 车载特化(安全影响加权)
6. 复测              ← 修复后验证闭环
7. 报告与移交        ← 模板见 templates/
```

## 车载漏洞评级特化

通用 CVSS 之外加权重：

| 维度 | 加权原则 |
|---|---|
| Safety 影响 | 涉及制动/转向/气囊 → 直接 Critical |
| 远程可达性 | 无接触远程 > 近场 > 物理 |
| 规模 | 影响整个车系/共享算法 > 单一配置 |
| 可复现成本 | 需要万元设备 vs 手机 APP |
| 修复难度 | 涉及硬件召回 vs OTA 可修 |

## 常用测试项清单（总线与诊断示例）

- [ ] 网关：跨域报文过滤是否白名单制？构造非法 ID/DLC/周期测试
- [ ] 诊断：0x27 seed 是否随机？key 算法是否可从固件逆向？失败次数限制？
- [ ] 诊断：未解锁状态下敏感服务（2E/31/34）是否拒绝？
- [ ] 总线：高优先级 ID 抢占（DoS）缓解措施（监控+总线恢复）
- [ ] secOC：重放旧报文是否被拒？计数器同步失败后的行为？
- [ ] OTA：签名校验绕过？降级安装？传输中断恢复？

## 证据链管理

每个漏洞必须可复现：**环境描述 + 版本信息 + 复现步骤 + 原始证据（pcap/log/照片）+ 影响分析**。准入审核时审查的是证据链完整度，不只是结论。
