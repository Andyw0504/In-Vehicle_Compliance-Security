# 05 · 合规落地与实践

> 从"读过法规"到"能干活"：体系文件怎么写、审计怎么应对、日常工作长什么样。

## CSMS / 汽车网络安全管理体系的文件框架

```
Level 1 政策层:   《汽车网络安全政策》《组织与职责》
Level 2 制度层:   风险管理程序 / 漏洞管理程序 / 事件响应程序 / 供应商管理程序
                  开发安全流程 / 变更管理 / 培训管理
Level 3 记录层:   TARA 报告 / 测试报告 / 漏洞台账 / 事件记录 / 内审记录 / 培训签到
```

审核逻辑：**说你所做（政策）→ 做你所说（记录）→ 持续改进（内审/管理评审闭环）**。

## 项目级合规工作流（车企/OEM 视角）

1. **立项**：条目定义（Item Definition）→ 确认边界与接口
2. **TARA**：按 21434 七步完成，风险处置输出网络安全目标
3. **概念**：网络安全概念，把目标分配到 E/E 架构（网关/TBOX/IVI/域控）
4. **开发**：需求分解、安全设计评审（HSM/安全启动/固件签名/secOC）、代码与工具链审查
5. **验证**：渗透测试（通常外委）、模糊测试、扫描，出具网络安全声明验证证据
6. **生产**：产线安全配置核查（密钥注入、调试口关闭）
7. **运维**：车队监控、PSIRT 运行、FedR 相关性判定、OTA 修复闭环
8. **准入证据包**：以上全部记录按审批机构要求整理

## 供应商/供应链合规（日常工作大头）

- 合同层：网络安全条款（漏洞通报 SLA、支持期限、责任划分）
- 能力层：供应商安全能力评估问卷 + 现场审核
- 执行层：联合 TARA、接口规范中的安全需求（DID/诊断权限/密钥管理）

## 渗透测试与合规的关系

- 车型准入**通常要求第三方渗透测试报告**作为验证证据
- 测试范围与 TARA 对齐：外部接口全覆盖（蜂窝/蓝牙/WiFi/OTA/诊断口）
- 报告要素：测试范围、方法、漏洞清单（严重度评级）、复现步骤、修复建议、复测记录

## 应对认证审核（内审员/接口人视角）

### 常见审核问题与准备

| 审核员问 | 你要拿得出 |
|---|---|
| 网络安全目标如何传递到供应商？ | 接口协议中的安全需求附件 |
| 新披露漏洞如何判定影响？ | FedR 流程文件 + 最近一次判定记录 |
| 事件响应演练做过吗？ | 演练方案+记录+改进项闭环 |
| 员工网络安全培训？ | 年度计划+课件+考核记录 |
| OTA 升级出问题怎么回滚？ | 升级管理程序+回滚机制说明 |

### 时间线管理

- CSMS 运行证据**至少覆盖 3 个月**再申请审核
- 年度监督审核前 1 个月完成内审
- 证书到期前 6 个月启动换证

## 学习方法建议

- 找公开材料练手：车企年报中的网络安全章节、审批机构（如 KBA/VTA）公开的审核要求
- 对标阅读：拿 21434 条款 → 自己起草制度 → 对照车企公开政策找差距
- 案例积累：关注 NHTSA/ISO/国内监管通报的召回与处罚案例
